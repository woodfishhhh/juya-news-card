## 编辑与卡片

1. 先核对原始来源和日期，完整文字稿保存全部合格消息。条数取决于实际材料，不把历史“精选 3–5”当上限；周报需覆盖整周，不能只做五条摘要。按看点排板块，板块内按看点排序，避免同一板块在时间轴上反复穿插。
2. 中英文独立自然撰写，事实与主题顺序一致。直接讲主体、新进展、数字、机制与用途，不用疑问句开场或悬念铺垫。保留影响事实的“公司称、论文报告、目标、预计、待合并”，不要在旁白或要点里反复塞“本期未独立复现、没有核验、仍需追踪”等制作备注；检查范围写入证据文件。
3. 第一页为本期概览。中文开场固定：大家好，我是木鱼，欢迎收看今天的具身智能晚报。播报结束固定：今天的具身智能晚报就到这里了，感谢你的收看，早点休息。双语版本使用自然对应译文；周报覆盖区间在概览显著标注。
4. **每页一个大主题，页内 4–6 块要点围绕同一主题。** 不能把不同公司或事件挤成摘要墙。保留原始日期、短来源和影响理解的“预计、作者报告、待合并”等状态。
5. 卡片使用 Juya 原生 SSR，实际加载、截图和布局核查全部通过 EGO。每轮复用同一个 TaskSpace，截图轮次重新设置 1920×1080。逐张打开实际 PNG 检查字体、裁切和重叠。
6. 截图前核对实际 DOM 正文与本期内容 JSON 一致，修改后使用新版本 query 或 reload，不依赖旧页面缓存。每次 EGO 截图重新确认 1920×1080。采用 compact-r2：4 点两列两行，5 点三列后居中两块，6 点三列两行；正文末端在 y=884 之前，为字幕留下安全区。日期和来源每页集中显示，避免每个要点重复占位。卡片输入与素材定稿后再开始渲染，不并发改写输入。

## 真实素材与时间轴

- 输出 1920×1080、30 fps、16:9，画面铺满。每个主题先展示卡片 2.5 秒，接连续真实图片或视频；只在最后 2.5 秒恢复卡片，不能用额外 PPT 代替素材。
- popup 目标框 1520×830，x=200、y=64；可遮住标题，顶部留距，保留素材比例。没有合适材料就记录缺口，不用无关画面充数。
- 每次素材进入有可见 popout 缩放，约 0.30 秒从小到正常尺寸，可有轻微回弹；同时卡片背景轻暗约 18%。连续媒体切换时保持素材可见，不淡出到纯卡片；只在末尾卡片恢复时还原背景亮度。导航与字幕保持清楚，禁止用白色混合把背景变亮。先制作短样片实际检查动效，再渲染全片。
- 通过 EGO 多找同主题真实图片与演示。普通图片单次从进入到退出最多 3 秒，复杂图例外须在素材时间轴保存 complex=true 及解释；不能一张图挂满主题。每段保存本地文件、显示起止、来源和哈希。
- 视频保留连贯动作，按内容需要播放 6–15 秒或更久，不受图片 3 秒上限限制。按 source_in / source_out 剪切不同片段，按片段原速播放，不使用 stream_loop、不循环或重复同一时间范围，跨主题也不复用同段；允许同源视频使用互不重叠的区间。随文稿长度补足素材：优先原文配图和原文视频，再补同主体的官方演示、现场照片、产品与技术资料；素材不足时继续查找，不能靠重复、冻结末帧或无关素材填满。
- 顶部为连续内容板块，底部为公司或事件；标签位置固定，宽度按真实章节时长分配。两条进度线共享帧时间和全局位置，持续单调推进；不随素材出现、字幕换句重置。字幕位于底部导航上方。
- 卡片出现即进入旁白（narration_offset_seconds=0），2.5 秒时弹出素材；卡片展示期间也显示当前语义字幕。开场时长取实际裁去首尾静音后的声音长度，不固定等满 5 秒。
- 主题之间精确留 0.5 秒（theme_gap_seconds=0.5、transition_mode=page-turn），在该区间内放一声短纸张翻页声。不要使用旧的 980Hz 正弦提示音；不另外叠加卡片淡出淡入等待。开场和片尾保持实际语音长度，旁白按真实样本安排，帧取整和变速窗长差分别记录。旁白、字幕、素材和导航共用时间轴。
- 保存素材原始 URL、观察时间、对应主题、SHA-256 和权利依据。公开可访问不能自动标为可公开再发布，私人审看与发布验收状态分开。

## 配音与音乐

- 先读本项目 [.codex/skills/minimax-tts-directing/SKILL.md](../.codex/skills/minimax-tts-directing/SKILL.md)，本机副本位于 C:/Users/woodfish/.codex/skills/minimax-tts-directing/。复用已有 mmx-cli 的 SDK 与认证：国内区 cn、speech-2.8-turbo、Podcast_girl。不从聊天复制密钥，不自动换音色或升级模型。
- 上游 speed=1.0、pitch=0，32 kHz / 128 kbps / mono MP3；渲染阶段 atempo=1.3，只加速一次。旧技能的默认 1.2 不适用本栏目。
- 按完整主题段落生成，不能将每条字幕分别合成。config/tts-pronunciations.zh.json 记录具体词的带调拼音；仅发送当前文稿实际包含的词。使用官方 pronunciation_dict={tone:["原词/替换读法"]}、非流式 text_normalization_mode=quality、subtitle_enable=true、subtitle_type=word。先做真实校音小样，保存回执、MP3 和提供方原始词时间戳；读音仍需核听。
- 2026-10-21 已核对 MiniMax 官方文档；mmx-cli@1.0.16 的读音参数拼装与现行官网格式不同，命令也未暴露全部精调字段。通过技能的 scripts/synthesize.mjs 发送完整 JSON，不修改已安装 SDK 或认证。离线 --validate 不读取认证、不产生调用。缓存键覆盖完整请求与地区；有音频缺字幕时恢复已有结果，不盲目再次付费。
- 以实际解码 PCM 样本数确定音频长度，只裁首尾真实静音，保留辅音与自然气口。提供方时间单位为毫秒；同一个拼音字典词可能返回多个音素行且共享原文字跨度，需要合并。英文多段返回的字符计数会省略段间空格，须逐段严格匹配原文并映射，不能按字数估时。
- 字幕参考本轮通过 EGO 实际观看的橘鸦 Juya 视频 BV1Ydnv65Esr（2026-10-21）：完整意思一行呈现，保护主谓宾、列举、数字单位和英文完整词；不逢逗号、顿号就切，不留下孤立 4–6 字短片段。白字配紧凑半透明灰底，约 40px、最大画面 82% 宽，通常随讲述持续 2–5 秒，按语义允许变化。超过单行宽度再在语义边界拆分；先画底板后画字。原文及其标点完整保留在数据，视觉可省略句末标点。
- 本地适配器 bin/juya_production.py 解码和单次加速后，将旁白、音乐与音效按全局整数样本位置拼装，再编码为单条 48 kHz 双声道 AAC；不再用多个独立 adelay 分支拼最终人声。原始 MiniMax 缓存仍为 32 kHz 单声道 MP3。
- 复用 D:\Coding\VideoFactory\public\ 中用户指定 MP3。第一首固定 boring life - db,Beteulan,BD DISCOMUSIC.mp3，其余每期随机一次，保存顺序与哈希，中英文及重试共用；同一期不重复、不循环填满。BGM 压在人声下，片尾淡出。
- 使用已有获授权配置，不充值，不将凭据写入源码、报告或制作包。保留实际接口错误，不能把有文件或 HTTP 200 当成配音成功。
- prepare-juya-audio.py 生成的曲目带 resolved_index，渲染器保留已确定的顺序，不进行第二次随机排列。

## 当前输入字段与维护

- content.json 的每种语言版本必须含 hostLine 和 closingLine；正文 sentences 保持完整句子。prepare-juya-audio.py 复用完整请求缓存，按主题生成自然旁白与提供方词级对齐字幕；开场使用用户最新完整欢迎词，不混淆旧短开场。
- 每个主题的 mediaSequence 保存独立素材片段：图片用 path、kind=image、seconds（普通图片不超过 3）；复杂图再填 complex=true 和 reason。视频用 path、kind=video、source_in、source_out、seconds，区间真实可解码。保存 SHA-256 和来源记录，先检查源视频内部是否自行重复；源区间不同也不能掩盖视觉上重复的同一镜头。
- 准备器保留每段视频的完整已编排时长，只对普通图片应用 3 秒限制；按中间窗口安排有限片段，只在末尾收束所需长度；不将所有视频平均压成三秒。将媒体排入各语言实际旁白时长，写出 media_sequence 的 start_seconds / end_seconds 与 frame_count；中间媒体片段必须首尾相接，不能插入纯卡片；不足时准备器报出缺少秒数，补素材后再继续。最后一个片段可以按所需时长结束，不循环或冻结补齐。顶底导航始终按全局帧时间推进。
- manifest 的 narration_captions 保存完整句级时间轴，captions 保存单行短语时间轴，开场和片尾分别保存同类字段。最终音轨验证使用 narration_captions，字幕核查使用 captions，不能把短语分段误当成新合成句子。
- juya_captions.py 基于提供方词级原文字跨度安排字幕，在完整意思、单行宽度和连贯显示之间分组。audio/phrase-alignment.*.json 保存方法；句级 narration_captions 供最终音轨验证，字幕 captions 保持全部原文，二者不要求同粒度。检查时间单调、全文覆盖及每个实际单行宽度。
- juya_media.py 使用有限视频解码器，EOF 必须失败，禁止循环或冻结补齐。juya_production.py 保留 0.30 秒 popout、18% 黑色背景压暗和轻微退出缩放；章节之间保留 0.5 秒并配纸张翻页声，供应商副本仍不修改。test/juya-production.test.py 包含字幕、整段音频、无额外留白、长视频保留、统一导航与歌单检查。
- 视频切片以确定的输出帧数限制，不叠加输出 -t；25→30 fps 转换曾因双重限制让 195 帧少一帧。渲染长片前，执行 bin/preflight-juya-media.py <期次目录>，对两种语言的每个实际视频切片预检全部计划帧，保留 verification/finite-clip-preflight.json，避免到长片中段才发现 EOF。

## 连续媒体窗口验收（r5）

- 每题 card_seconds=2.5、closing_card_seconds=2.5、media_layout=continuous-bookends。中间窗口为 [75 帧, 章节总帧数-75 帧)，所有片段连续覆盖，不得存在卡片补时或一帧纯卡片闪回。
- 新媒体以可见缩放进入，切换时保持媒体可见及背景轻暗；退出到卡片只发生在最后 2.5 秒。每段保存起止、源区间、哈希和原页面。普通图片至多 90 帧，复杂图须确有内容密度与讲解依据。
- 原文应检查懒加载图库、轮播、嵌入视频等首屏之外的素材；视频应实际打开查看并选择不同源区间。相关产品/技术资料可作为背景画面，不能标成新现场；例如 Digit 产品演示不能冒充尚未开始的 AGCO 试点。长稿补多份素材，不用同一图片或重复镜头拉长。
- 最终 MP4 检查每个媒体交界、首尾各 75 帧卡片、10 个精确 15 帧题间区间、翻页声实际音轨定位，以及每句最终 AAC 和单行字幕。

## 2026-10-23 接入更新

继续沿用本项目 JuyaCard 与固定 vendor 渲染器。新期次使用 `media_binding_policy=sentence-v1`；素材按 `binding.sentence`（从零开始）、`binding.text`（完整句原文）、可选 `binding.offsetSeconds`（最终播放秒）关联到 `narration_captions`。同一绑定允许多张图或多个有限视频片段，组间切换取实际句时间 / 1.3；头尾 2.5 秒、0.5 秒题间、图片 3 秒与不重复规则继续执行。历史 manifest 可复放，不追溯重做已接受成片。

仅改画面时执行 `bin/prepare-juya-media.py <期次目录>` 预检，确认后加 `--write` 写回，两种语言先全部计算成功再写入，不调用 TTS。完整配音准备器同样要求绑定且生成新策略 manifest。

新渲染自动在 MP4 sidecar 保存 productionBinding。技术核验输出 productionIdentity；实际审片与用户验收使用 `bin/review-juya.py` 显式记录证据，不能由渲染成功自动批准。独立封面使用 `bin/build-juya-cover.py <期次目录>`，不取视频第一帧。发布前验证成片和封面的当前审片版本。格式、失败恢复和命令见 [融合接入说明](integration-workflow.md)。
